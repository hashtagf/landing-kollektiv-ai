# Plan: TH/EN i18n for landing site

## Summary
Add an in-house, typed i18n layer to the landing site with TH as the default and EN as a switcher option in a new top-right header. Resolution order: `?lang=` → `lang` cookie → TH default. All hardcoded copy in the five section components moves into typed dictionaries.

## Approach
Build a lightweight client-side i18n (no `next-intl`) since the App Router page is fully client-rendered already (every section uses `'use client'`). Create `src/i18n/` with `config.ts`, `types.ts`, and `dictionaries/{th,en}.ts`. Wrap children in a new `LanguageProvider` (React Context, `'use client'`) that:

1. On mount, reads `?lang=` (via `useSearchParams`); falls back to a `lang` cookie; falls back to `th`. Validates against supported locales; invalid values fall through.
2. Exposes `{ lang, setLang, t }` where `t` is the active dictionary (typed via `Dictionary` derived from `th.ts` so TS catches missing keys in `en.ts`).
3. On `setLang`, writes the cookie (1-year, `SameSite=Lax`), pushes `?lang=<code>` via `router.replace` (preserves scroll), and updates `document.documentElement.lang`.

The server `RootLayout` reads the `lang` cookie via `next/headers` so the initial `<html lang>` matches the cookie (avoids a hydration flash for returning visitors); the provider reconciles with `?lang=` post-mount. New `Header.tsx` is fixed top-right and renders `LanguageSwitcher.tsx` only — no nav links (out of scope). Each section component replaces inline strings with `t.<section>.<key>`. Page-level `metadata` exports stay English (server-rendered hreflang variants are explicitly out of scope).

## Files to touch
- `src/i18n/config.ts` — new; `LOCALES = ['th','en'] as const`, `DEFAULT_LOCALE = 'th'`, cookie + query-param names.
- `src/i18n/types.ts` — new; `Locale` and `Dictionary` types (derived from `th` via `typeof`).
- `src/i18n/dictionaries/th.ts` — new; full Thai dictionary covering Hero, About, Services, Team, Contact (labels, placeholders, validation messages, submit states), plus the switcher's aria-labels.
- `src/i18n/dictionaries/en.ts` — new; English dictionary, same shape (typed as `Dictionary`).
- `src/i18n/LanguageProvider.tsx` — new; client context, hooks `useLanguage()` and `useT()`.
- `src/components/LanguageSwitcher.tsx` — new; TH/EN toggle button group, `aria-pressed`, keyboard-accessible.
- `src/components/Header.tsx` — new; fixed top-right wrapper that mounts `LanguageSwitcher`.
- `src/app/layout.tsx` — read `lang` cookie via `cookies()`, set `<html lang={initialLang}>`, wrap `{children}` in `<LanguageProvider initialLang={initialLang}>`, render `<Header />`.
- `src/components/Hero.tsx` — replace heading/subtitle/CTA/trust-indicator strings with `t.hero.*`.
- `src/components/About.tsx` — replace section copy with `t.about.*`.
- `src/components/Services.tsx` — replace service titles/descriptions and chart labels with `t.services.*`.
- `src/components/Team.tsx` — replace member roles, bios, section copy with `t.team.*` (names stay literal).
- `src/components/Contact.tsx` — replace headings, form labels, placeholders, validation messages, submit/loading/success states with `t.contact.*`.
- `src/i18n/__tests__/dictionaries.test.ts` — new; key-parity test (TH vs EN).
- `src/i18n/__tests__/LanguageProvider.test.tsx` — new; resolution-order tests.

## Test plan
- First-visit no-cookie load renders TH (covers AC #1).
- Switcher visible top-right and reflects active lang via `aria-pressed` (covers AC #2).
- Click EN: every visible string in all 5 sections re-renders in English; grep `src/components` for Latin/Thai literals as audit (covers AC #3).
- Reload after selecting EN → still EN; cookie inspected = `lang=en` (covers AC #4).
- Visit `/?lang=en` with cookie=th → renders EN and cookie flips to `en` (covers AC #5).
- Toggle switcher → URL gains `?lang=<code>`; copy/share URL renders same lang in fresh session (covers AC #6).
- Dictionary parity test fails build if a key exists in `th` but not `en` or vice versa (covers AC #7).
- `/?lang=fr` falls back to TH (or current cookie) without crash.
- `<html lang>` attribute updates on toggle (DOM assertion).
- `npm run build`, `npm run lint`, `npm test` all pass; no hydration warning in dev console after toggling.

## Risks / open questions
- **Hydration vs. query param**: the server layout can read cookies but not `searchParams`, so when a visitor lands on `/?lang=en` with cookie=th, the first paint uses cookie=th and the client reconciles to `en` post-mount. Acceptable flash, or should we ship a tiny middleware to rewrite the cookie before render? Defaulting to "acceptable" given Out of Scope on SEO meta variants — Founder, confirm.
- **Thai copy source**: who provides the TH translations? I will draft idiomatic TH from the EN source; please flag if a native reviewer should sign off before merge.
- **Header styling**: the site has no existing header — I will ship a minimalist fixed top-right container so the switcher doesn't compete with Hero. If a fuller nav is wanted later, it slots into this same `Header.tsx`.
- **Metadata translation**: page `<title>`/`<meta description>` stay English per Out of Scope; confirm this is acceptable for TH-default visitors.
