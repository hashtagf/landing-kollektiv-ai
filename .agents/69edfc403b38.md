# Plan: Migrate landing-kollektiv-ai from Vercel to Railway

## Summary
Stand up a Railway service for the Next.js 14 landing site, generalize deploy-metadata env vars (Vercel → Railway), strip Vercel-specific config from the repo, then pause the Vercel project once Railway is verified green.

## Approach
Railway auto-detects Next.js via Nixpacks, so the repo only needs a small `railway.json` to pin `buildCommand`, `startCommand` (binds to `$PORT`), restart policy, and the `/api/health` healthcheck. The two metadata routes (`health`, `status`) get a tiny shared helper that prefers `RAILWAY_*` env vars and falls back to `VERCEL_*` so the response is non-null on Railway and during the cutover window. The Vercel-specific GitHub Actions deploy jobs are deleted (Railway deploys via its own GitHub integration on push to `main`); lint/test/build-test jobs stay. `vercel.json` is removed and its unique headers (Permissions-Policy, SW + static asset cache) are folded into `next.config.js` so security/cache parity is preserved. Cutover steps (Railway env-var seeding from Vercel, smoke tests, pausing the Vercel project) are documented in a runbook so the Founder can execute them outside the repo.

## Files to touch
- `railway.json` (new) — `buildCommand: npm ci && npm run build`, `startCommand: npm start -- -p $PORT`, `healthcheckPath: /api/health`, `restartPolicyType: ON_FAILURE`.
- `src/lib/deployment.ts` (new) — `getDeploymentInfo()` returning `{ region, url, gitCommitSha, gitBranch, deploymentId, platform }` with `RAILWAY_*` first, `VERCEL_*` fallback.
- `src/app/api/health/route.ts` — replace inline `VERCEL_*` block with `getDeploymentInfo()`; nest under `deployment` (drop the `vercel:` sub-key).
- `src/app/api/status/route.ts` — same swap; rename fields to platform-neutral (`region`, `url`, `git_commit`, `git_branch`, `deployment_id`, `platform`).
- `next.config.js` — add `Permissions-Policy` header and `Cache-Control` rules for `/sw.js` and `/(.*\.(css|js|...))` (migrated from `vercel.json`).
- `vercel.json` — **delete**.
- `.github/workflows/ci-cd.yml` — delete `deploy-preview` and `deploy-production` jobs and the `VERCEL_*` env block; keep `lint-and-test`, `build-test`, `security-scan`. Drop the `validate-routes` step that depended on the Vercel preview URL.
- `.kollektiv/runbooks/railway-cutover.md` (new) — env-var checklist (`MONGODB_URI`, SMTP creds, any `NEXT_PUBLIC_*`), Railway service-create steps, smoke-test commands, Vercel pause/delete steps, rollback (re-enable Vercel project).
- `README.md` — replace the Vercel deploy section with Railway equivalents.

## Test plan
- Local: `npm ci && npm run build && PORT=4000 npm start` — confirm bind to 4000 (covers AC #1).
- Railway deploy from `main` succeeds; open generated `*.up.railway.app` URL; homepage + key sections render (AC #1, #2).
- `curl https://<railway-url>/api/health` → 200, `deployment.git_commit_sha` populated from `RAILWAY_GIT_COMMIT_SHA`, `platform: "railway"` (AC #5).
- `curl https://<railway-url>/api/status` → 200, `deployment.deployment_id` non-null, metrics block intact (AC #5).
- Mongoose connectivity: hit any DB-touching route (currently none in `src/`, but if `MONGODB_URI` is set, no startup connection errors in Railway logs) (AC #3).
- Email: submit contact form on Railway URL; verify delivery + Railway logs show no SMTP errors (AC #4).
- Redeploy: push trivial commit to `main`; new SHA appears in `/api/status` (covers redeploy edge case).
- Cutover: Vercel project paused → `curl https://landing-kollektiv-ai.vercel.app` returns 404/paused page (AC #6).

## Risks / open questions
- `MONGODB_URI` and SMTP creds aren't referenced anywhere in `src/` today — confirm whether the Founder still needs them seeded in Railway or if they're vestigial deps that can be dropped from `package.json` later (out of scope for this task; just port them as-is).
- Does the Founder want a Railway custom domain swap eventually? Out of scope per issue, but the Vercel project may be aliased to a custom domain — confirm there's no DNS dependency before deletion (pause first, delete after a soak period).
- `next start -p $PORT` syntax via npm requires the `--` separator; if Railway's shell quoting trips on it, fall back to `npx next start -p $PORT` in `railway.json`.
- The `deploy-preview` GitHub Action posts PR comments — removing it changes PR UX. Confirm Railway's PR-environments feature isn't being relied on (out of scope per issue, so we drop without replacement).
